# Merqora — Razorpay Test Mode Setup

Merqora only ever talks to Razorpay in **Test Mode**. No real money moves.
If `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` / `RAZORPAY_WEBHOOK_SECRET` are
left blank, the app automatically falls back to `RazorpayMockAdapter` (see
`docs/architecture.md §7`) so you can develop and demo without a Razorpay
account at all — but for the strongest demo, use real Test Mode keys.

## 1. Create a Razorpay account

Sign up at [dashboard.razorpay.com](https://dashboard.razorpay.com/). A free
account is enough — Test Mode does not require KYC/activation.

## 2. Switch to Test Mode

Razorpay's dashboard has a **Test / Live** toggle in the top navigation
ribbon. Test Mode is a full sandbox: it behaves identically to Live Mode,
except no real payments are processed. ([Razorpay Docs — Test and Live
Modes](https://razorpay.com/docs/payments/dashboard/test-live-modes/))

## 3. Find your Test API keys

1. In the Dashboard, make sure **Test Mode** is selected.
2. Navigate to **Settings → API Keys** (or **Account & Settings → API
   Keys** depending on dashboard version).
3. Click **Generate Test Key**.
4. You'll be shown a **Key Id** and **Key Secret** once — download/copy
   both immediately. Razorpay does not store or re-display the secret.
   ([Razorpay Docs — API Keys](https://razorpay.com/docs/payments/dashboard/account-settings/api-keys/))

## 4. Never expose the secret key

- `RAZORPAY_KEY_ID` → safe to reference from the frontend (Merqora fetches
  it via `GET /api/payment/config`, never bundles it into frontend code).
- `RAZORPAY_KEY_SECRET` → **backend only**. It is read from `process.env`
  inside `src/lib/razorpay.ts` and never appears in any API response,
  frontend bundle, or log line (see the redaction logic in
  `src/lib/logger.ts`).

## 5. Configure a webhook

1. In the Dashboard (Test Mode), navigate to **Account & Settings →
   Webhooks → Add New Webhook**. ([Razorpay Docs —
   Quickstart](https://razorpay.com/docs/payments/quickstart/))
2. Webhook URL:
   - Local dev: expose your backend with a tunnel (e.g. `ngrok http 4000`)
     and use `https://<your-ngrok-subdomain>.ngrok.io/api/webhooks/razorpay`.
   - Production: `https://<your-render-service>.onrender.com/api/webhooks/razorpay`.
3. Select at minimum these events: `payment.captured`, `payment.failed`,
   `payment.authorized`.
4. Set a **Webhook Secret** in the same form — this is a value *you* choose
   (not generated by Razorpay), used to sign the payload.

## 6. Add the webhook secret to `.env`

```
RAZORPAY_WEBHOOK_SECRET="the exact same value you entered in the dashboard"
```

## 7. Configure `apps/api/.env`

```
RAZORPAY_KEY_ID="rzp_test_xxxxxxxxxxxx"
RAZORPAY_KEY_SECRET="xxxxxxxxxxxxxxxxxxxxxxxx"
RAZORPAY_WEBHOOK_SECRET="whatever_you_set_in_step_5"
```

Restart the backend (`npm run dev:api`) after editing `.env`.
`GET /api/payment/config` should now return `{ "mode": "production", ... }`
— "production" here means "the real Razorpay adapter," which in your case
is still pointed at Test Mode keys, so no real charges occur.

## 8. Test a payment end-to-end

1. Go to `/agent-commerce` (Sable, the AI Buyer) in the running app.
2. Ask for a product (e.g. "I need running shoes under ₹5000"), add one to
   cart, click **Proceed to Checkout**.
3. Razorpay's checkout widget opens. Use a **test card**:

   | Field | Value |
   |---|---|
   | Card number | `4111 1111 1111 1111` (Visa) |
   | CVV | any 3 digits |
   | Expiry | any future date |

   A mock bank page appears with **Success**/**Failure** buttons — pick one
   to simulate that outcome. ([Razorpay Docs — Test Card
   Details](https://razorpay.com/docs/payments/payments/test-card-details/))
4. On success, `POST /api/payment/verify` runs server-side signature
   verification and marks the order `PAID` only if it matches.

## 9. Inspect the webhook

- Razorpay Dashboard → **Account & Settings → Webhooks** → click your
  webhook → **Recent Deliveries** shows the payload, response code, and
  whether it succeeded.
- In Merqora, every inbound webhook (valid or not) is stored as a
  `WebhookEvent` row and visible indirectly via the Audit Log
  (`WEBHOOK_PAYMENT_CAPTURED` / `WEBHOOK_PAYMENT_FAILED` /
  `WEBHOOK_CONFIRMED_ALREADY_CAPTURED` actions).

## 10. Test a payment failure

On the mock bank page shown in Test Mode, click **Failure** instead of
**Success**. Razorpay returns a failure response and (if configured) fires
a `payment.failed` webhook. Confirm in Merqora that:

- the Order stays in `PENDING` (never `PAID`),
- the `Payment` row is `FAILED` with a `failureReason`,
- an `AuditLog` entry exists under category `PAYMENT`.

You can also exercise this without touching the real Razorpay checkout at
all via **Failure Lab → Payment failure** in the merchant dashboard, which
performs the same signature-verification code path against a deliberately
invalid signature.

## 11. Troubleshooting

| Symptom | Likely cause |
|---|---|
| `GET /api/payment/config` returns `"mode": "mock"` even after setting keys | One of `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` / `RAZORPAY_WEBHOOK_SECRET` is still blank — all three are required to activate the production adapter. Restart the backend after editing `.env`. |
| Webhook shows "failed" in Razorpay's Recent Deliveries | Check the webhook URL is publicly reachable (tunnel running, or deployed backend URL correct), and that `RAZORPAY_WEBHOOK_SECRET` matches exactly what's configured in the dashboard. |
| `SIGNATURE_INVALID` on `/api/payment/verify` | This is often *expected* if you clicked "Failure" on the mock bank page — that's the correct behavior, not a bug. |
| Real card details don't work in Test Mode | Expected — Test Mode only recognizes Razorpay's published test card numbers, never real cards. |
